# Как писать страницы справки

Справка — для **пользователя**, не для разработчика. Страница описывает
поверхность и её механику так, чтобы читатель понял, как устроено, и не
перечитывал список кнопок.

Эталон тона — исходная `ui/buttons.md`
(`git show 5ceef84e:src/resources/help/ru/ui/buttons.md`): проза-контекст,
понятия, а не инвентарь. Но и у неё есть плохие приёмы (см. §1.3, §1.5) —
не копировать их.

Факты — только из **исполняемого кода** (обработчики, конструкторы меню,
редьюсеры, порядок layout). Комментарии, docstring'и и старые i18n-словари
устаревают и врут — не источник.

---

## 1. Голос

**1.1. Номинантный док, не обучалка.**
Описываем, что поверхность *есть*. Не ведём по шагам.
- Плохо: *«Управляйте сессиями… открывайте типы сравнения… Нажмите… затем…»*.
- Хорошо: *«Страница выбора новых вкладок и истории проектов.»*

**1.2. Подлежащее — поверхность, не «вы».**
Grep: `\bвы\b`, `\bваш\b`, `\byou\b`, `\byour\b`.

**1.3. Без вопросов-ярлыков в буллетах.**
`**Где** — …`, `**Что** — …`, `**Насколько плотный** — …` — брак. Это не
справка, а анкета; пользователь и так видит, где что. Пункт называет
понятие и говорит по делу.

**1.4. Императив — максимум один короткий на секцию, без цепочек.**
Один жест-императив допустим (*«Перетащите файл проекта на панель…»*),
стек из трёх (*Выберите / Перетащите / Переключайте*) — брак.

**1.5. Без мета-нарратива о замысле.**
Пользователю не нужны объяснения, зачем дизайнер так сделал: *«чтобы
больше места осталось картинке»*, *«удобно мышью»*, *«проще понять»* —
вырезать. Инженерное «почему» живёт в design-доке, не в справке.
Допустимо лишь следствие, которое прослеживается к коду и важно
пользователю (инвариант безопасности: «файлы остаются на диске»).

**1.6. Без описания расположения кнопок словами.**
`«кнопка на тулбаре открывает…»` — плохо. Назвать действие; где оно —
покажет подпись к рисунку.

**1.7. Без эмодзи.** Рендер их не поддерживает; в каноне их нет.

**1.8. Без таблиц-инвентарей клавиш на страницах табов.**
Полный список — в `platform.hotkeys`. На странице таба: аккорд внутри
определения (`**Поменять** (`X`) — …`) либо одна строка + ссылка.

## 2. Структура

**2.1. По поверхностям и понятиям, не по шагам и не по контролам.**
Заголовки — существительные. Страница читается в любом порядке секций.

**2.2. Иерархия, не плоское микроперечисление.**
Один пункт — одно понятие, одна короткая фраза. Группировать похожее;
потолок ~6 пунктов на `###`, глубже — своя секция или вон. Семь равных
пунктов, мешающих переименование, удаление, кросс-таб и константу, — брак.

**2.3. Открытое множество — механизм + «например». Закрытое —
перечислять с опорой на код.**
Вкладки, типы сессий, плагины — ОТКРЫТОЕ (карточки строятся из пакетов
табов; можно подключить бесконечно). Цементировать список — брак, он
устареет (старый словарь с двумя типами — тому доказательство).
- Плохо: *«Типы сессий — Сравнение изображений, Мультисравнение,
  Галерея.»*
- Хорошо: *«Карточки всех подключённых вкладок, например Сравнение
  изображений или Галерея.»*
ЗАКРЫТОЕ (аккорды одного действия, константы вроде `max_slots=12`,
фиксированный список метрик) — перечислять, но с трассировкой к коду.
Слова *все / каждый / только* требуют опоры.

**2.4. Имена — из `tr`-паков владельца.**
`{{tr:image_gallery.tab_name}}` → «Галерея», не сленг «ИИ галерея». Сленг
ломает поиск и Find Action.

**2.5. Ссылаться, а не дублировать.**
Секция, повторяющая соседнюю страницу, — вырезать; дать `help://`-ссылку.
`### Next topics` можно, `### Related`-свалку нельзя.

**2.6. Не мешать уровни.**
Системные вещи (клавиатура, поиск, настройки окна) не размазывать по
странице одной вкладки — у них свой раздел (`platform.*`). Страница таба
описывает только свою поверхность, с ссылкой на общее.

**2.7. Скелет.** `##` заголовок + 1–2 предложения лида + `###`-секции со
стабильными `{#anchor}` + опциональный `### Next topics`. Существующие
якоря не переименовывать.

## 3. Факты (код — истина)

**3.1. Любое утверждение — к исполняемой строке или зелёному тесту.**
Перед написанием открыть код: обработчики действий, конструкторы меню,
редьюсеры, порядок layout'а. Перечислить их в черновике ревью: не
уверен, что код это делает, — не пиши.

**3.2. Ловушки этой сессии (проверено в коде; старое содержимое врало):**
- Одиночный файл в галерее открывается один, родитель НЕ сканируется.
- Фокус слота в мультисравнении — одиночный клик, не двойной.
- «Set as source» задаёт эталон; анализ перезапускается, победителей не
  пересчитывает.
- Режим fidelity не включается автоматически.
- AI-запрос требует: включено + ключ + модель (не только ключ).

**3.3. Против «попугайства» комментариев.**
Разведка и автор обязаны читать КОД. Ревьюер берёт 2 случайных
утверждения на страницу и сверяет со строками кода. Факт, подпёртый
только комментарием/докой, — переписать или вырезать.

**3.4. Дальнозоркость.**
Понимать механику шире цитируемой строки (напр. что список вкладок
открыт), иначе страница цементирует неверную модель и сгниёт. Если
поведение зависит от конфигурации/плагина — писать механизм, а не
случайный срез.

## 4. Вычитка и фальсификация (перед сдачей)

**4.1. Перечитать документ целиком одним проходом.**
Провал сессии: выше «переименования нет», ниже секция «Переименовать». Так
нельзя. Проверить: нет внутренних противоречий, секции читаются в любом
порядке, понятие не определено дважды по-разному.

**4.2. Вычитать скомпилированную страницу, не `.md`.**
Опечатки (`.:`, лишние запятые), сырые токены (`{{tr:}}` без значения =
нет ключа → починить i18n), битые `{{img:}}`, мёртвые `help://`. RU и EN
оба, если оба поставляются.

**4.3. Проб-фальсификация — 2–4 на страницу.**
Например: «уронить один файл → соседи не подхватились»; «выключить
каждый из трёх AI-параметров → проверить строку ошибки».

**4.4. Заморожено (на переписывании — diff пустой):**
наборы `{#anchor}`, ключи `{{tr:}}`, цели `help://`, блоки `:::figure`,
заголовки `##`/`###`. EN-first, в `ru|zh|pt_BR` EN не копировать
(фолбэк). Бюджет рисунков — потолок из таблицы. Форма сценарных карточек
(`##` + `###`).

**4.5. Grep запрещённого:** `\bвы\b`, `чтобы (вы|удобно)`, `нажмите.*затем`,
`кнопка на тулбаре.*открывает`, `\bГде\b.*—`, эмодзи, аккорд-таблица вне
`hotkeys`, `все/каждый/только` без опоры.

---

## 5. Открытые решения

- Рисунок `session_picker#tab-strip`: бюджет 0 (текст достаточен; поднять —
  отдельным решением).
- `max_slots=12` — оставляем с опорой на константу (закрытое, видно в
  тосте «сетка заполнена»).
- RU — номинантный стиль как EN (`«Клик открывает»`), одиночные
  императивы по §1.4; опечатки чинятся молча.
