# Plan: рефакторинг текста справки

Полный рефакторинг тел справки: привести все страницы к
[HELP_AUTHORING.md](./HELP_AUTHORING.md).

Область: все `resources/help/<lang>/*.md` — host (`src/resources/help/`),
табы (`src/tabs/*/resources/help/`), плагины
(`src/plugins/*/resources/help/`), во всех поставляемых языках.

Не-цели: механика справки (дерево, merge, токены, фигуры, рендер); новые
фичи; структура дерева (только если рефакторинг текста вскроет
смешение уровней — тогда отдельным решением).

## Принцип

План задаёт объём и фазы, но **не** предписывает конкретные формулировки
и постатейные замены. Что и как менять в каждой странице — определяет
автор по гайдлайну и коду, ревьюер проверяет соответствие. Никаких
заранее зашитых «убрать X, заменить на Y» — это останавливает понимание
на моём срезе вместо чтения кода.

## Фазы

1. **Базлайн** — зафиксировать обращения к help (якоря, `help://`-цели,
   фигуры, ключи) и зелёные help-тесты как референс для каждой волны.
2. **Переписать все страницы** по гайдлайну, по одной поверхности за
   волну, начиная с показательной. Порядок — по владельцу, не по
   важности: host → табы → плагины.
3. **Ревью** — по гайдлайну, со сверкой фактов к коду.
4. **Доки** — привести `HELP_SYSTEM.md` и профильные доки в соответствие.

## Верификация (каждая волна)

- Гайдлайн §4: полное перечитывание, вычитка скомпилированной страницы,
  проб-фальсификация, grep запрещённого.
- Help-сuites, `check_help_figures.py`, `test_docs_link_graph` — зелёные.
- Изменения в механиках (якоря/ссылки/фигуры/дерево) — только если
  осознанны, зафиксированы и покрыты тестом.

## Риски

- Гайдлайн против канона: образец тоже содержит брак; правится.
- Смешение уровней может потребовать структурных решений — выносить
  отдельно, не протаскивать молча.
